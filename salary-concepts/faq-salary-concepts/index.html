    FAQ for Salary Concepts in Omne RH Payroll¶

    Why can't I edit the IRPF Exempt and In Kind fields directly?¶

    These fields are automatically inherited from the Perception Key assigned to the concept. This design ensures that all concepts with the same perception key have consistent fiscal treatment. To change the value, either modify the perception key in the Perception Keys master or assign a different perception key to the concept.

    What is the difference between Subject to Contribution and Contribute on Proration?¶

    Mode Behavior Typical use
    Subject to Contribution = Yes The concept contributes to social security every month it appears in payroll Base salary, fixed bonuses, agreement supplements
    Contribute on Proration = Yes The concept only contributes when it is earned, distributing the contribution proportionally Quarterly commissions, annual bonuses, irregular variable concepts

    To enable Contribute on Proration: first set Variable to Yes, then set Subject to Contribution to No, then set Contribute on Proration to Yes. The order is mandatory.

    What happens when I propagate changes if a scheme has custom conditions?¶

    Propagation updates structural fields (Subject to Contribution, Accounting Group, Prorate, Variable, Subconcept, Perception Key, IRPF Exempt, In Kind) but never modifies amounts, formulas, or units/price in the scheme. Individual employee compensation conditions remain intact.

    Why are earnings automatically set to "According to SMI" for garnishment?¶

    This is by design for Earning type concepts. Spanish law establishes that salaries are garnishable according to a scale based on the minimum interprofessional salary (SMI). The system applies this rule as the default. If a concept should not follow this rule (for example, an indemnification), manually set its garnishment to Not Garnishable or Fully.

    When should I use the Provision field, and what do the values mean?¶

    Value Effect Use case
    (empty) No provision Regular monthly concepts
    Variable Provisioned and de-provisioned when earned Extra pays provisioned monthly and settled at payment
    Without De-provision Provisioned but no de-provision generated Concepts accumulated without periodic settlement

    The Extra Pay No. field must be set before configuring the provision.

    What does "system concept" mean and what are the limitations?¶

    System concepts are predefined records that cannot be deleted. If you try to delete one, the system shows: "You can't erase predefined concepts for the system." You can modify their properties (description, accounting group, etc.) but their existence is protected because the payroll engine references them internally.

    Can the same code exist for different concept types?¶

    Yes. The primary key is the combination of Code + Concept Type. A concept SB of type Earning and another SB of type Bases are independent records with different properties. When searching or referencing a concept, the system always filters by type.

    What is the difference between "Excluded Part Time" and Quantity Management "Excluded Part Time"?¶

    Field Effect
    Excluded Part Time (field) The concept amount is not prorated proportionally to the part-time contract hours
    Quantity Management = Excluded Part Time The quantity (units) is not adjusted for part time, but the amount may still vary

    Both fields protect the concept from automatic part-time adjustments, but they act on different dimensions (amount vs. quantity).
