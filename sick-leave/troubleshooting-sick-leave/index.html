    Troubleshooting Sick Leave Issues in Omne RH Payroll¶

    Common problems and solutions when working with the Sick Leave module.

    Cannot load the FIE file¶

    Symptom: The system shows a message that the FIE file cannot be loaded.

    Solution: 1. Verify the file path is correct and the file exists. 2. Confirm the file is not open in another application (SILTRA, text editor). 3. If the file is compressed (.zip), extract it before importing. 4. Open the file in a text editor and verify: - The first line starts with ETI. - The last line starts with ETF. - Intermediate lines start with valid codes (EMP, TRA). 5. Download the file again from SILTRA and retry.

    Employee from FIE file not found in the system¶

    Symptom: The import report shows "Employee with the indicated NAF not found."

    Solution: 1. Open the employee card and verify the affiliation number (NAF) matches exactly (12 characters). 2. If the NAF is incorrect in the system, correct it. 3. If the employee does not exist, register them before importing. 4. For multi-company environments, verify the contribution account (CCC) maps to the correct company.

    Payroll already exists in the period¶

    Symptom: The import report shows the error "A payroll already exists in this period."

    Solution: 1. Identify which payroll exists in the affected period. 2. Void the payroll for the corresponding period. 3. Re-import the FIE file. 4. Recalculate the payroll to reflect the incident changes.

    Confirmation reports (PC) do not trigger this error, so you do not need to void payrolls for confirmations.

    An incident already exists in the same period¶

    Symptom: The system indicates an incident already exists in the same period for the employee.

    Solution: 1. Check the existing incidents for the employee. 2. If the previous incident is still open (no end date), close it first with the discharge date. 3. If dates overlap, adjust one of the incidents so they do not overlap.

    Relapse cannot find the original incident¶

    Symptom: The FIE file reports a relapse but the system cannot find the original incident.

    Solution: 1. Review the employee's past incidents. 2. If the original incident was never registered, create it manually with the correct data before importing. 3. Verify the original incident is closed (has an end date). You cannot create a relapse from an open incident.

    Missing discharge cause code when generating FDI file¶

    Symptom: Error indicating the discharge cause code is missing in a discharge report (PA).

    Solution: 1. From Incidents, go to the Siltra group and choose RED Data Query. 2. Locate the discharge report (PA) with the error. 3. Open the report card and fill in the Discharge Cause Code field (for example: Cure, Permanent Disability Proposal). 4. Regenerate the FDI file.

    Missing required fields in the Delta accident report¶

    Symptom: Validation errors when generating the accident report.

    Common missing fields and where to fill them:

    Missing field Location
    Accident date General section of the accident details card
    Injury causing material agent Accident classification section
    Physical activity material agent Accident classification section
    Healthcare facility type Medical data section
    Injury severity Medical data section
    Employee phone number Employee card (not the accident card)

    Solution: 1. Open the accident details card. 2. Complete all fields indicated by the error. 3. Verify at least one preventive modality is marked (or mark "None"). 4. Choose Validate Data to confirm all required fields are filled. 5. Regenerate the accident report.

    Incident code not found when importing FIE¶

    Symptom: The import report indicates no incident code exists for the notified contingency.

    Solution: 1. Choose the search icon, enter "Incident Codes", and choose the related link. 2. Verify records exist for the necessary types: - At least one code with Incident = Illness (for common contingencies) - At least one code with Incident = Accident (for professional contingencies) - A code with Incident = Maternity (for maternity/paternity benefits) 3. For special IT situations (menstruation, pregnancy interruption, week 39 of gestation), verify codes exist with the corresponding Special IT Situation value. 4. Verify the Contingency Code field is filled in the incident codes.

    CCC not recognized in multi-company FIE file¶

    Symptom: When importing a FIE file with employees from multiple companies, some are not resolved correctly.

    Solution: 1. Verify the contribution unit has the main contribution account (11 digits) correctly entered. 2. Confirm the company is registered in the system configuration. 3. For first imports, the system creates mapping records automatically during processing.

    When to contact technical support¶

    Contact support if: - The FIE file loads but produces systematically incorrect results - Contribution base calculations do not match after verifying payroll data - Internal errors unrelated to missing data appear - Delta report validation keeps failing after completing all required fields - RED reports show as unsent after correctly generating the FDI file
